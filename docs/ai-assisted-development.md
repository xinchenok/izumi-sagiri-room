## 先说明：仍然没有训练语音模型

V20 继续使用 Piper Plus「つくよみちゃん」公开预训练模型做本地推理，新增二十四句日语日常台词。没有训练、微调、动画音轨、真实声优声纹克隆或参考音频；也没有宣称是原作配音。模型、配置和推理源码使用固定 revision 与 SHA-256，见 [V20 配音来源](../assets/audio/v20/VOICE-SOURCES.md)和[逐句清单](../assets/audio/v20/voice-manifest.json)。

## V20 使用的协作方式与已知工具限制

- **Impeccable**：确定角色主导的房间体验、批准构图和区域规格，记录视觉差异；不是把图片直接作为整页 UI。
- **ImageGen**：逐图参考编辑与日夜光照编辑。原始输出保留，图像生成不能保证重新调用后逐像素一致。
- **Playwright**：真实浏览器中的路径、键盘、状态、图片档位及故障情境验证。五套九态明暗矩阵已检查，但不把资产矩阵当作整站视觉验收。
- **Neat-freak**：将新实现与历史来源分开，同步文档与待验收状态，不在最终汇报和用户确认之前自动清场。
- **独立协作**：人物／房间／字体／配音／验证按写入范围拆分，主流程集成；代码复核发现的取消、环境声、观察器按钮、收藏与字幕问题由唯一主 writer 修复，再只读复查对应 delta。

初始整帧图像相似度达到 0.88 以上，但 Impeccable 的逐控件像素 gate 未接受中文字体和对比度调整，强制跳过请求也被拒绝。该 gate **没有通过**，差异报告仍保留在 `.impeccable/review/diff/hero`。实现继续以已批准样稿为构图参考，真实可读性、无障碍和独立完成审查仍须分别验证，不写成“全部工具已通过”。

最终 detector 仅执行一次，回执记录 `runCount: 1`、`exitCode: 0`、`truncated: true`，存在 warnings，不能据此称无问题通过。独立文档代理已将 DESIGN 与 sidecar 同步为实际 V20；独立审查确认标题对比度约 8.40:1、箭头、手机手笔板坐标及 200% 观察清晰度四项修复均 resolved。F1 逐像素工具流程仍为 unresolved，formal disposition 保留 fix。真实音频、`file://`、CI、Pages 及正式站指纹与交互结果已进入发布凭证。

### 页面、角色与交互

- 从零建立“门外轻敲—获得回应—进入房间—探索画桌—翻衣橱与画册—听晚安”的完整单页叙事，并保持零框架、无后端、无运行时外部依赖。
- 根据和泉纱雾“怕生、重度家里蹲、认真画画、被夸时会嘴硬和害羞”的角色锚点统一文案与场景；所有服装和画面坚持全年龄、日常化、非性感化，不复制官方截图。
- 首屏提供偷看、受惊、害羞和认真得意四种表情。访客敲门后先出现受惊过渡，再打开房门；门板、人物图和状态文案使用同一演出状态，不会出现两个互相冲突的开门结果。
- 加入初次拜访、逐渐熟悉和主动留门缝三个回访阶段，根据有效拜访次数与间隔更新门牌、开门反应和隐藏留言，不显示签到、经验值或好感度数值。
- 建立统一反应停靠区，让敲门、换装、秘密、画册、晚安和语音都在同一处更新人物表情、场景标签与反馈，避免多套浮层互相遮挡。

### 雨夜共同创作与具体记忆

- 在画桌与衣橱之间加入“今晚，陪她画完这一张”：访客依次选择陪伴方式、小猫主题、草莓 / 薄荷 / 银蓝配色和一句具体感想；所有选择都可直接使用、可返回修改、可重新画，没有正确答案或失败状态。
- 制作专注、自然眨眼、被认真夸奖后的害羞、把完成稿推近四个连续人物帧，以及“门缝看月亮”“被窝里画星星”“抱着大铅笔”三张奶油稿纸小画；舞台只在进入视口后加载眨眼帧，害羞与完成帧只在开始互动后预取。
- 以雨线、台灯呼吸、笔尖微光和 145ms 自然眨眼让画室有生命；动画只在章节可见、页面前台、人物空闲时运行。减少动态效果下停止随机眨眼并隐藏雨线与笔尖微光。
- 将 `presence`、`subject`、`palette`、`praise` 和完成时间写入现有 `sagiri-room-state-v2.sharedDrawing`；旧状态没有该字段时保持兼容。再次回来时，桌边会出现上次成稿，并自然复述陪伴方式、配色和具体感想。
- 选项均为原生按钮，支持 Enter / Space、可见焦点、44px 触控与 `aria-pressed`；步骤变化由 `aria-live` 宣布，完成后焦点落到“再陪她画另一张”，图片加载失败仍保留文字与选择流程。
- 该章节不加入签到、打卡、积分、好感度、经验值、成就、抽卡、排行榜、奖励货币或内容锁；停留价值来自共同创作、角色反应和可见作品，而不是机械留存系统。

### V7 会生活的连续房间

- 在开门后的房间介绍中加入统一 4:3 取景框和可可木滑轨，让访客在画桌、床边、衣橱和窗台之间移动；桌面使用“房间画面 + 右侧重叠稿纸”，手机按“画面—稿纸—横向木轨”堆叠，不把地点做成四张卡片或地图关卡。
- 画桌复用 V6 专注 / 眨眼帧，床边与窗台复用 v4 已验收画册场景；只为缺少横向机位的衣橱生成一张 1448 × 1086 新图和 720 × 540 移动版，背景同时保留床、窗与画桌以证明仍是同一间房。
- 每个地点都提供一组可重复的小事件和三条轮换反馈：补完一笔、递回毯角、扶稳衣架、关小窗缝；重复操作会变化台词和局部画面，但不计数、不奖励、不锁内容。地点另有停留约 5.6–9.2 秒后出现的自主细节，不弹任务或提示。
- 本地时间选择清晨、午后、傍晚、夜里和深夜的灯光与短句；细雨 / 晴月明确标记为“房间里的天气”，由访客随时切换，不联网、不冒充真实气象、不制造限时内容。
- 使用 FFmpeg 噪声源与包络制作笔尖、布料、衣架、窗帘 / 雨声四段 0.94–1.38 秒本地短拟音；只在用户操作后播放，不自动播放、不循环，并使用独立“房间声”开关。最终页面播放峰值约 -20～-23 dB，手机扬声器可感知但不会压过角色语音。
- 将 `livingPlace`、`livingWeather` 与 `roomSoundMuted` 写入现有 `sagiri-room-state-v2`；旧 V6 状态没有字段时回落到画桌、细雨和开启拟音，不清空服装、秘密、回访、画册、语音偏好或共同作品。
- 上次 V6 共同完成的小猫画以桌边拍立得真实出现；重新完成作品后立即更新。没有作品时不显示空相框，不把记忆变成次数、收藏值或好感度。
- 四地点支持鼠标 / 触控点击、方向键和手机横向滑动；场景图禁用浏览器原生拖图并捕获活动指针，横滑不会吞掉垂直页面滚动。减少动态模式下停止自主换帧并隐藏雨线、笔尖、布料、衣架和窗帘动作，地点、事件、天气、文字与拟音开关仍完整可用。
- 完整素材路由、衣橱提示词、拟音制作方向、导出规格与 SHA-256 见 `docs/living-room-v7-assets.md`。

### V8 房间声音与雨窗边界

- 修复连续房间的雨线覆盖室内问题：床边不显示雨线，画桌、衣橱和窗台只在各自右侧窗玻璃范围出现，宽度小于取景框的 40%，不再覆盖人物、木地板或整间房。
- 为画桌、床边、衣橱和窗台分别新增一条地点开场语音与三条事件语音；雨起和雨停另各一条，共十八条房间专属日语语音。它们全部由 `CONTENT.livingRoom.voices` 管理，不读取或复用主线 `CONTENT.voiceLines`。
- 使用 Piper Plus 0.6.0 与 `ayousanz/piper-plus-tsukuyomi-chan` 预训练模型本地合成；没有提供参考音频或说话人克隆向量。最终文件为 44.1 kHz、单声道、160 kbps MP3，并按约 -17 LUFS 统一响度。
- 将原先四段 V7 单声道拟音替换为十二段地点事件声和两段天气声；十四段均为不同的 48 kHz、立体声、192 kbps 文件。雨起 / 雨停不再借用窗台关窗或窗帘声音。
- 把“房间声”明确改名为“场景声”；它只控制物件 / 天气声。“只看角色字幕”只控制角色语音，关闭任何一方都不会连带关闭另一方。
- 新增本地 Noto Sans JP 字体子集，解决无系统日文字体环境中字幕假名显示方框的问题；日语字幕显式使用 Noto，中文视觉仍沿用原字体职责。
- 机器可读文本、模型 revision、合成参数、时长、哈希、十四段场景声和验收合同见 `docs/room-audio-v8.md` 与 `assets/audio/v8/*-manifest.json`。

### V9 音频响应与真实雨窗

- 复现旧播放器在 1.2 秒媒体等待下“点击后才发请求”的问题：房间语音约 1298ms 才进入播放状态，连续点击还会通过共享 `src` 互相中断加载。
- 为每个语音与场景声文件建立独立播放器；对应按钮或连续房间进入预备范围、房门首次打开时，以低网络优先级完整读取本地音频并转换为页面内 Blob 源。点击不再替换共享播放器地址，未准备完会立即显示状态，瞬时预热失败则重新加载仓库原文件。
- 同样 1.2 秒人为媒体等待下，预热后的点击不新增网络请求，桌面受控 Chromium 多轮实测约 65–85ms 进入播放状态；故障注入确认第一次预热失败后仍能重试播放。
- 再次按原始插画核对室外区域：画桌与共同创作只保留右上玻璃，衣橱只保留最右上窄玻璃，窗台只保留月亮所在的右上玻璃，床边完全隐藏。雨层宽度不超过取景框 19%、高度不超过 21%，不再压到人物、窗帘、窗框、灯具、桌面、床或地板。
- 桌面与手机逐项触发十八条房间角色语音和十四段场景声，确认每个点击仍启动自己的文件；两套雨景完成边界数值检查和实际截图复核。

### V10 逐窗格 Canvas 雨与重制窗雨声

- 调研 Canvas 粒子雨、按玻璃裁剪的多遮罩和高采样率室内窗雨录音的共同特征后，删除覆盖整个共同创作章节的斜纹雨背景，以及房间 / 画室两组等距 CSS 雨线。

- `motionMode` 以 `lively` / `quiet` 写入 `sagiri-room-state-v2`，旧状态缺失时回落到 `lively`；安静模式停止连续混合、自主反应、雨景与视差但保留内容和主动交互。系统 `prefers-reduced-motion` 始终具有最高优先级并禁用站内切换。
- 七幕图片清单为 `assets/v19/manifest.json`：8 张 3072 × 3840 竖版人物、18 张 3840 × 2880 场景，共 26 张母版、96 个 WebP。`assets/archive/pre-v19-cinematic-images.json` 记录切换前 107 个 V18.1 WebP，旧图不删除、不覆盖、不移动。
- 首轮 ImageGen 新图虽然动作正确，却被用户明确指出棕橙、颗粒、油画与整体脏感。该批次随后全部隔离，没有进入运行时；主 agent 先生成一张平整明亮的校准图，再把全部镜头逐张重新编辑为清爽 TV 动画赛璐璐，最后只用 Pillow Lanczos 做尺寸转换与 WebP 编码，不添加锐化、纹理、降噪或调色。
- 独立完成审查继续按“画面里真的存在，热点才能出现”复核语义：`room-invites-seat` 重绘为明确拉出薄荷椅子，`drawing-covers-page` 重绘为真正用稿纸盖住数位屏，`goodnight-wave` 重绘为抱着玩偶与书在门边挥手；观察模式改用包含三个物件的稳定帧、完整 `contain` 显示与实际图片矩形热点映射，反应帧期间暂时隐藏热点。

### 二十二句语音、字幕与情境分流

- 用 AivisSpeech Engine 1.2.0 和预训练模型“天深シノ”独立合成二十二句日语回答；没有训练、微调、克隆真实声优声纹，也没有截取动画音轨。
- 四个入口分别对应门口、画桌、夸画与晚安。十八句普通回答以轻声、普通、开心和害羞为主，各入口使用洗牌队列，一轮听完前不重复，换轮时也避免首尾紧邻重复。
- 将四句明显不高兴的 `ふきげん` 回答从普通随机池彻底移出；只有门口或画桌同一入口在 5 秒内连续触发 4 次才会播放一次，随后冷却 25 秒，下一次普通操作回到可爱语音池。
- 每个回答对象同时绑定日文、简体中文字幕、表情、场景名和本地 MP3，避免音频与字幕错配；开始新语音前会停止旧语音。
- 增加音量、停止和“只看角色字幕”控制，并保存音量与静音偏好；音频加载失败时继续显示完整字幕与视觉反应，不调用系统 TTS，也不自动播放声音。
- 为全部二十二句保存最终 MP3、完整 `audio_query`、模型与风格信息、时长和 SHA-256 清单，保证后续可核验和受控复现；模型包、引擎缓存、中间 WAV 和临时下载不进入运行时提交。

## 历史角色插画的制作方式

本项目没有使用官方截图。插画工作流如下：

1. V19 继续以 `assets/v18/master/hero-peek-4k.webp` 锁定银白长发、蓝眼、粉色发饰、圆润可爱脸型、细小嘴型、自然脸红和全年龄比例，并以一张清爽画桌校准图锁定平整明亮的 TV 动画赛璐璐画风。
2. 每张旧图只承担构图与动作参考：保留姿势、手势、道具、机位、主体裁切和房间几何，不继承旧图的颜色、纹理、笔触或人物五官。
3. 第一轮 V19 新图被用户指出明显棕橙、颗粒、油画与脏感；该批次随即整体隔离，没有挑图混入现役矩阵，也没有用后期锐化掩盖问题。
4. 主 agent 先完成一张干净校准图，随后将 26 个七幕镜头逐张重新编辑为平整无纹理色块、最多两档硬边阴影、冷白银发、清透肤色和浅木家具；动作、手部和组内机位逐张复核。
5. 最终 ImageGen 源图再由 `tools/build-v19-images.py` 使用 Pillow Lanczos 纯缩放与高质量 WebP 编码，生成 3072 × 3840 竖版或 3840 × 2880 场景母版及响应式派生图；不添加锐化、纹理、降噪或调色滤镜。
6. 精确提示词保存在 `assets/v19/prompts`，每个 WebP 的同名 `.webp.json` 保存来源与导出方法；`assets/v19/manifest.json` 汇总 26 张母版、96 个 WebP、尺寸、哈希、锚点和对应旧图。
7. 所有画面要求全年龄、非性感化、无图片内文字、无水印、无多余人物或肢体，不复刻官方截图。

`assets/v19` 是七幕连续镜头的现役目录；原有页面区段仍使用自己的 V18 / V18.1 资产。V19 没有删除、覆盖或移动旧图，切换前 107 个 V18.1 WebP 的路径、尺寸、大小和 SHA-256 见 `assets/archive/pre-v19-cinematic-images.json`。完整 V19 合同见 `docs/v19-cinematic-room.md`，V18 历史流程见 `docs/v18-4k-image-redraw.md`。

## V4 主线二十二句不同回答如何生成

### 角色化写法

四类互动分别是房门口、画桌旁、被夸以后与晚安以前。普通池共有十八句独立日文文本，以“轻声、短句、害羞但会一点点放松”为主；涉及画稿时更认真，被夸时会先确认是不是客套。另外四句 `ふきげん` 回答属于连续催门或催稿的情境反馈，不进入普通随机。它表达的是本页角色设定与情境，不照录动画台词，也不冒充真实声优。

运行时数据保存在 `script.js` 的 `CONTENT.voiceLines`。`chooseVoiceReply()` 为每个普通入口维护一份洗牌队列：当前入口的普通回答全部弹出前不会重复；重新洗牌时若队首会与上一轮末句相同，会先交换位置。`shouldUseGuardedReply()` 只在同一入口 5 秒内触发 4 次时放行情境池，并设置 25 秒冷却；这四句不会被 `chooseVoiceReply()` 选中。字幕、表情、反应文字和音频路径都来自同一个回答对象，因此不会出现“声音换了但字幕没换”的错配。

### 合成与可复现文件

- AivisSpeech Engine：1.2.0。
- 同一模型：天深シノ；模型 UUID、说话人 UUID、模型包 SHA-256、风格 ID、每句文本、参数、时长与输出 SHA-256 全部保存在 `assets/audio/v4/voice-manifest.json`。
- 根据句意使用同一模型提供的 `ささやき`、`ノーマル`、`じょうきげん` 或 `ふきげん` 表达；普通随机池不含 `ふきげん`，`pitchScale` 始终为 0，没有用后期移调制造不同音色。

### 本地合成流程

1. 安装并启动 AivisSpeech，让本地 Engine 正常运行。
2. 安装“天深シノ”模型。
3. 请求 `GET /speakers`，根据模型 UUID、说话人名称和风格名称读取当前安装实际返回的 `styles[].id`。
4. 对每句文本调用 `POST /audio_query` 生成查询参数。
5. 将查询 JSON 传给 `POST /synthesis`，保存返回的 WAV。
6. 把 WAV 放入 `assets/audio/v3/`，并核对 `script.js` 中的文件路径、日文台词、中文字幕和表情映射。

AivisSpeech Engine 默认提供与 VOICEVOX 兼容的本地 HTTP API。下面是 PowerShell 示例；执行前必须先从 `/speakers` 核对当前风格 ID：

```powershell
$engineBase = "http://127.0.0.1:10101"

# 先查看当前安装实际提供的说话人与风格 ID。
$speakers = Invoke-RestMethod -Method Get -Uri "$engineBase/speakers"
$speakers | ForEach-Object {
  $speaker = $_
  $speaker.styles | ForEach-Object {
    [PSCustomObject]@{
      Speaker = $speaker.name
      Style = $_.name
      Id = $_.id
    }
  }
} | Format-Table

# 用刚刚核对出的 ID 生成一条语音。
$lineText = "お、おかえり……今日も、静かにしてね。"
$styleId = 1063997411
$escapedText = [Uri]::EscapeDataString($lineText)
$queryUri = "$engineBase/audio_query?text=$escapedText&speaker=$styleId"
$query = Invoke-RestMethod -Method Post -Uri $queryUri
$queryJson = $query | ConvertTo-Json -Depth 100 -Compress
$queryBytes = [Text.Encoding]::UTF8.GetBytes($queryJson)

Invoke-WebRequest `
  -Method Post `
  -Uri "$engineBase/synthesis?speaker=$styleId" `
  -ContentType "application/json" `
  -Body $queryBytes `
  -OutFile "assets\audio\v3\welcome.wav"
```

旧版的四个原始文件为 44.1 kHz、单声道 WAV。v3 页面曾从该场景的原始 WAV 和两段后期 MP3 中随机选择；当前 v4 页面已经改为二十二句独立回答。开始新回答前仍会停止上一段；播放失败时保留日文、简体中文字幕和视觉反馈，且不会回退到系统 TTS。

以上记录了旧版 WAV 校验值；v4 已为全部二十二句保存完整 `audio_query`、引擎版本和机器可读清单。
