# 房间专属配音、真实场景声与窗雨

- 最近更新：2026-08-20（V15 窗台无杂音独立拟音）
- 用户目标：每一个房间地点、事件与天气状态都使用自己的配音和场景声，不从页面其他段落借用，也不在房间事件之间复用
- 运行边界：全部音频随静态站点本地发布，只在明确操作后播放，不自动播放、不循环、不调用系统 TTS；接近交互时只做静音预热，不把加载误当成播放
- 机器清单：角色语音与天气声见 [`assets/audio/v8/voice-manifest.json`](../assets/audio/v8/voice-manifest.json) 和 [`assets/audio/v8/scene-sound-manifest.json`](../assets/audio/v8/scene-sound-manifest.json)；十二段现役地点事件声见 [`assets/audio/v14/scene-sound-manifest.json`](../assets/audio/v14/scene-sound-manifest.json)

## 合成来源与后期

房间语音使用 [Piper Plus 0.6.0](https://github.com/ayutaz/piper-plus) 与 [ayousanz/piper-plus-tsukuyomi-chan](https://huggingface.co/ayousanz/piper-plus-tsukuyomi-chan) 预训练模型本地生成。模型卡声明训练数据来自[つくよみちゃんコーパス](https://tyc.rei-yumesaki.net/material/corpus/)；页面页脚长期保留模型来源和语料条款链接。

- 没有采集角色动画音轨，没有训练、微调或克隆藤田茜等真实声优声纹。
- 没有提供参考音频或说话人克隆向量；按 Piper Plus Python 参考实现，在模型要求前向兼容输入时传 256 维零向量与 `speaker_embedding_mask=0`，回退到训练声线。
- 合成参数固定为 `language=ja`、`noise_scale=0.667`、`length_scale=1.5`、`noise_w=0.8`。
- 原始输出为 22.05 kHz 单声道 WAV；最终经过 70 Hz 高通、10.5 kHz 低通和 `I=-17 / TP=-1.5 / LRA=7` 响度处理，编码成 44.1 kHz、单声道、160 kbps MP3。
- 十八个最终文件的实测综合响度约为 -15.2～-18.3 LUFS，峰值约为 -1.9～-2.8 dBFS；每个文件都能由 FFmpeg 解码。

模型与配置本身不进入仓库；清单保存模型 revision、模型 SHA-256、完整文本和最终音频哈希，便于以后核对来源与变化。

## 十二段真实事件拟音与两段天气声

V14 用十二份不同的 Freesound CC0 现场录音替换原先十二段程序化事件拟音。画桌、床边、衣橱与窗台各三次操作分别对应数位笔、桌面滑动、单次按键、被毯、床单、靠枕、衣架、布料、带衣物的衣架、真实关窗、画纸滑动和窗帘轨道；每份来源只截取一次与动作相符的物件表演，不从同一录音拆出多个事件。完整来源页、原文件规格、官方预览哈希、截取区间、输出哈希与处理参数见 [`assets/audio/v14/ROOM-FOLEY-SOURCES.md`](../assets/audio/v14/ROOM-FOLEY-SOURCES.md)、机器清单和 [`tools/build-room-foley-v14.mjs`](../tools/build-room-foley-v14.mjs)。

V15 再替换窗台的关窗、画纸和窗帘三条来源：三份原录音本身都只记录一次短动作，运行片段去掉点击前空白，也不再从长录音末尾截取。这样可排除录音者说话、呼吸与收设备尾音，同时让关小窗缝保持室内近场的轻滑轨声；三条均不烘焙雨底，晴月状态不会错误听见雨。

十二个 V14 运行文件均为 48 kHz、双声道、192 kbps MP3，只做 65 Hz 高通、16 kHz 低通、响度处理与短淡入淡出，不叠加白噪声、合成冲击、算法混响或变调层。V7 的四段与 V8 的十二段程序化事件拟音仍留在仓库供历史复现，但 `script.js` 已没有运行时引用。

雨起与雨停继续分别使用 `assets/audio/v8/weather-rain-window.mp3` 与 `assets/audio/v8/weather-clear-window.mp3`，不借用窗台的关窗或窗帘文件。窗台三次操作也不固定混入雨声，因为房间允许处于“晴月”状态；窗雨只由天气操作承担。十二段事件拟音与两段天气声都不是自动播放或循环环境音，只承担一次明确操作的声音反馈。

V11 的雨起声来自 nicoproson 的 [`RAIN on glass window.wav`](https://freesound.org/s/648529/)：原作品是室内视角的轻雨窗玻璃录音，发布规格为 96 kHz、32-bit、立体声 WAV、2:53.931，并以 CC0 1.0 发布。仓库生成脚本取得 Freesound 官方 HQ 预览并先核对 SHA-256，再取第 44–68 秒，做 70 Hz 高通、`I=-23 / TP=-4 / LRA=8` 响度处理、80 ms 淡入和 800 ms 淡出。最终文件实测 24.024 秒、-22.7 LUFS、真峰值 -4.2 dBFS；没有叠加程序化白噪声或合成雨滴。来源、取得哈希和完整处理合同见 [`assets/audio/v8/RAIN-SOURCE.md`](../assets/audio/v8/RAIN-SOURCE.md) 与 [`tools/generate-rain-window-audio.mjs`](../tools/generate-rain-window-audio.mjs)。

## Canvas 窗雨与室内边界

V7 雨线曾铺满整个房间取景框，容易产生“室内在下雨”的误读；V8 / V9 又把数根等距 CSS 线放进单个近似矩形，虽然变窄，仍会跨过真实窗框并显得重复。V10 删除整个暗房章节的斜纹雨背景和两套固定 CSS 线，改用透明 Canvas 按原图像素坐标裁剪可见玻璃，但窗格仍是近似矩形：衣橱左上矩形在顶部跨进窗帘，窗台左上矩形也把人物头发遮挡区算进玻璃。

V11 把三组窗格全部改为原图像素坐标多边形。每个顶点沿真实窗帘轮廓、人物头发、灯具遮挡和倾斜横框内缩，运行时再按 `object-fit: cover` 与 `object-position` 映射；每块多边形单独建立路径并 `clip()`，因此窗框与遮挡物会切断雨痕。画桌、衣橱、窗台与共同创作仍使用不同种子，床边在隐藏前也会清空画布缓冲。共同创作不再固定下雨，而是读取同一个 `livingWeather` 状态；切到晴月后，房间和共同创作画布的非透明像素都必须归零，初始标签同步变为“截稿前的晴夜”。

## 点击响应与预热

旧实现让角色语音和场景声分别共用一个播放器；每次点击都先停止旧音频、替换 `src`、调用 `load()`，慢网与连续点击会产生可见等待，前一次加载也可能被后一次替换。当前实现为每个音频文件保留独立播放器，并在对应语音按钮或连续房间进入预备范围、房门首次打开时，以低网络优先级完整读取文件、转换为本页 Blob 源。预热本身没有 `play()`，因此仍然符合“只有用户操作后播放”。

- 内存源已经就绪时，点击直接从本地 Blob 开始，不再临时发媒体请求或替换共享 `src`。
- 尚未就绪时立即显示“正在准备”，本次点击仍可使用仓库内原文件播放。
- 预热请求瞬时失败时不锁死条目；媒体元素会重新加载原文件，后续点击可以恢复。
- 新点击仍停止上一条角色语音或场景声，过时请求的 `AbortError` 不覆盖当前字幕和状态。

## 控制与失败降级

- “只看角色字幕”只静音角色语音；触发后仍展示日文、简体中文字幕、场景标签、表情和反应。
- “场景声”只控制十四段物件 / 天气声；关闭后不能连带静音角色语音。
- 两类声音都不会在地点切换、进入视口或自主动画时自动播放。
- 新语音会停止上一条角色语音；每段场景声有自己的缓存播放器，仍不进入角色音量控制。
- 角色音频加载失败时保留双语字幕并显示可恢复说明；场景声失败时保留地点事件、画面和文字状态。

## 日语字幕字体

原有 ZCOOL KuaiLe 字体不含完整日文假名。V8 新增 Noto Sans JP 当前页面字符子集 `assets/fonts/NotoSansJP-Room-Subset.woff2`，只让 `lang="ja"` 的字幕优先使用它，并保留 [`OFL-NotoSansJP.txt`](../assets/fonts/OFL-NotoSansJP.txt)。页面仍不远程热链字体。

## 验收

发布前必须继续满足以下门禁：

- 桌面 1440 × 1000 与手机 390 × 844 实际点击：4 条地点语音、12 条事件语音、2 条天气语音全部是十八个不同 V8 文件。
- 同样路径确认 12 段事件声全部引用 `assets/audio/v14`、对应 12 个不同来源 ID、文件哈希与 V14 清单一致；2 段天气声保持独立，场景声关闭后角色语音仍可播放。
- 故障注入阻断 `room-desk-intro.mp3`，双语字幕与错误说明仍保留。
- 床边画布缓冲为零；画桌、衣橱、窗台和共同创作舞台的每个非透明 Canvas 像素都必须落在映射后的玻璃多边形内（只允许路径抗锯齿产生的低透明边缘像素），不覆盖人物、窗帘、窗框、灯具或任何室内物件；画桌与共同创作使用不同随机种子。
- 细雨切到晴月后，房间与共同创作两张 Canvas 的 alpha 总和都必须为零、可见透明度为零，共同创作初始标签为“截稿前的晴夜”；重新切回细雨后才恢复绘制。
- 1440 × 1000 与 390 × 844 逐场景截图检查 Canvas 映射；绘画章节本体与伪元素的 `background-image` 都必须为 `none`，不再用整段斜纹冒充雨。
- `weather-rain-window.mp3` 必须保持 48 kHz、双声道、192 kbps、24.024 秒，并与清单 SHA-256 一致；生成脚本必须先核对 CC0 来源文件哈希，输出可解码音频且无 NaN / Inf / 反常削波。
- 在每个音频请求人为增加 1.2 秒等待的条件下，预热后的房间配音点击不新增网络请求，受控 Chromium 实测约 65–85ms 进入播放状态；首次预热故障注入后可由原文件重试并成功播放。
- 受控 Chromium 截图确认日语字幕无方框缺字，桌面和手机均无横向页面溢出。
- `node --check script.js`、两个 JSON 清单解析、全部音频解码、资源引用、UTF-8 无 BOM与乱码特征扫描通过。
